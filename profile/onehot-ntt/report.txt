HISTORICAL BENCHMARK REVISION
The performance numbers below were measured before the merge of main e423a390 (2026-10-23). Main changed the SIS security policy and schedule geometry. These timings and historical proof hashes are not measurements of the updated branch. The K=16 schedules are regenerated for the new policy; current validation is recorded separately in main-sync-validation.json. Reproduction compares variants within each fresh run.


Workload: nv=38 (2^38), k_chunk=16, recursive mode; root D=512, rank=1, width=65536, 8192 live blocks.
MacBook M4 Max and Leopard Ryzen 9 9950X. Both release builds use -C target-cpu=native; selected final thread counts are recorded below.
Same setup, opening point, and independent resident random witness reused for all full-size trials within each host.
The five-prime panel reads the existing six-prime root matrix directly. The exact limb-split backend needs its own additional prepared public-matrix representation; its fastest timing assumes that representation is already prepared. Both cases include all witness work.
The witness is 32 GiB of random Option<u8> indices, not a repeated block. No disk-backed witness fixture.
Preprocessed public matrix NTTs are prepared before timing. Witness decoding, conversion, forward NTT, pointwise dot, inverse NTT and exact CRT reconstruction are timed.

WHAT CHANGED
Final exact-NTT preparation uses RHS bound 2, matching the existing basis-2 validator for binary 0/1 input. The initial sweep used the protocol basis-3 bound 4. This removes an unnecessary public limb on the MacBook (1.25 GiB to 1 GiB root exact cache) while leaving the witness and protocol unchanged.
1. Direct decoding of one-hot indices into reusable bounded column tiles. No sparse-entry materialization and no witness gadget decomposition; higher digit planes are zero.
2. Block panels reuse the same preprocessed matrix columns across independent blocks. Tested B=1,2,4,8,16 and C=24,48,96,192,384 combinations, including prefetch on/off.
3. Five-prime exact CRT uses the one-hot ring L1 bound h=ceil(D/k_chunk), instead of the dense D bound. The full output bound is floor(q/2)*width*h, requiring CRT product strictly greater than twice that bound.
   At nv38, D512 and width65536, the five-prime safe width is 131040. Existing six-prime matrix entries are consumed through their first five limbs without copying or retransforming A.
   Larger widths split at the proven capacity, reconstruct each partial exactly, and add in the field. Forced small-capacity chunks are exercised by differential tests at both D256 and D512.
4. Existing SIMD conversion, radix-4 transforms, six-column lazy pointwise dot and once-per-output reconstruction are retained; no new competing butterfly implementation.
The reduced-prime path retains the original six-limb matrix storage (768 MiB at the root); it saves transform/dot arithmetic without allocating a separately transformed five-limb A. The final exact root cache is an additional 1 GiB on the MacBook; raw logs contain total cache and preparation costs.
5. Existing exact signed-i16 NTT backend is benchmarked through its canonical cache, including its existing split-public-matrix/IFMA52 selection on x86. Direct one-hot decode supplies binary i16 coefficients.
6. Binary twist selection is tested as an alternative conversion; screen and full-size data show whether its loss of the fused conversion path is worthwhile.
7. Leopard screens both default AVX2 and explicit AVX-512 in fresh processes. The best screened SIMD plan is used for the full-size family comparison.
8. All selected arithmetic families run complete proofs; the fastest completed verified NTT trial is automatically repeated twice, bracketed with a repeated accumulation run.
